## Layers

<!-- Profile chosen at Gate B: strict (5 layers). -->

| Layer | Responsibility | May import from |
|---|---|---|
| `domain` | Models and use-case contracts | — (nothing) |
| `data` | Use-case implementations + data protocols | `domain` |
| `presentation` | Controllers, boundary validation, boundary errors | `domain` |
| `validation` | Composite validators | `presentation` |
| `infra` | In-memory store, library adapters | `data` (protocols) |
| `main` | Factories, composition | all |

**Import rule (verifiable):** no file in a layer imports from a layer not in its
"may import from" column. A third-party library appears only in `infra` (and in
`main` if a framework is introduced). In this slice the only cross-layer types
are the use-case contracts in `domain` and the data protocols in `data`.

## Boundaries / Adapters

|---|---|---|

## Per-layer test conventions

| Layer | Test type | Reference skill |
|---|---|---|
| `domain`/`data`/`presentation` | Unit with test doubles and `makeSut()` | `testing/test-doubles`, `testing/test-setup-factories` |
| `validation` | Unit (composite returns the first error) | `foundational/input-validation` |
| `infra` | Integration with the in-memory store | `testing/integration-tests` |
| `main` | Factory-built controller + real in-memory store | `testing/integration-tests` |
