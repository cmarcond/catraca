# Tasks — How to Decompose and Check Off

One file per feature, `NNN-slug.md` (same number as the spec), generated by
`/catraca.implement` from the spec + skills. Use `TASKS-TEMPLATE.md`.

> **Two numbering schemes.** Feature 000 (the quality pipeline) uses `T0.x`
> **chore** tasks — there is no red/green/refactor; each tool is a chore, and
> the equivalent of "red" is a gate proof (provoke a violation, watch it get
> rejected). See `TASKS-000-TEMPLATE.md`. Product features use `T1, T2, …
> T-final` with full red/green/refactor.

## Rules

1. **One task = one behavior**, not a file. It comes from the smallest
   observable rule (skill `tdd-minimal-step`).
2. **Every task is born three-phase**: red / green / refactor sub-items. The red
   records *which assertion* should fail; checking the red without having seen
   the test fail is a gate violation.
3. **Order follows the layers**: domain/data behaviors before presentation;
   infra (adapters) once the protocol exists; main last (composition + routes).
4. **The checkbox is the state.** There is no other record of progress. A task
   is done = three phases checked + the `method.md` gates verified.
5. **One commit per task** (if commits are required), message
   `type(scope): imperative description`.
6. Evaluation tasks (rubric + ratchet) go in as the feature's last task.
