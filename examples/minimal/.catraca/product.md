## Objective

A small backend for running polls. An organizer can create a poll (a question
with a set of answer options); later, people can list the open polls and cast a
vote. This example exists to demonstrate the Catraca method end-to-end, so the
scope is deliberately tiny.

## Users

- **Organizer** — creates polls and reads the results.
- **Voter** — lists the open polls and casts a single vote.

## What success is

- An organizer can create a poll with a question and at least two options, and a
  malformed poll is rejected with a clear reason.
- A voter can see the list of open polls.
- A voter can cast a vote that is recorded against the chosen option.

## Candidate features

1. Create a poll

## Out of scope

<!-- What deliberately does NOT go into this version. -->

- Authentication and user accounts (any caller is trusted for this example).
- Closing polls, editing, or deleting them.
- Persistent storage across restarts (an in-memory store is enough here).
- A real HTTP server / deployment (controllers are exercised directly).
