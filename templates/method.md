## Operationalized gates

Before marking any task as done, the agent verifies:

- [ ] **G-Test-First**: the behavior's test failed before the implementation,
      on the assertion (not on setup/import).
- [ ] **G-Layers**: no import violates the table in `architecture.md`.
- [ ] **G-Adapter**: no third-party library imported outside `infra`/`main`.
- [ ] **G-Coverage**: coverage did not drop (the profile's target above).
- [ ] **G-Commit**: a commit in the format `type(scope): imperative description`
      covering only this task (if commits are required).

Violations are allowed only with a justification recorded in the feature's
rubric (`evaluation/NNN-*.md`, the "justified violation" column) — and they
count against the score according to the evaluation mode.

**Mechanical enforcement:** these gates do not depend on the agent's discipline.
The **feature 000 (quality pipeline)** — mandatory before any product feature —
installs hooks that reject them automatically on every commit: strict
type-check, zero-warnings lint, commit-message validation, pre-commit with
lint+tests over the staged files, and a coverage gate (skill
`workflows/quality-pipeline`: "automatic gates, not discipline"). The agent
verifies; the hook rejects.
